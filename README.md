# АвтоМастер24 — безопасная версия: каталог исполнителей без сбора данных клиентов

**Сайт:** https://avtomaster24bot-lab.github.io/avtomaster-vezu-safe/
**Основа:** дизайн и часть кода из [avtomaster-vezu](https://github.com/avtomaster24bot-lab/avtomaster-vezu) (прежний репозиторий не менялся).

Каталог СТО, эвакуаторов, моек, магазинов запчастей, выездных мастеров и грузоперевозчиков Казахстана. Принцип простой:

- **Клиент** ничего не оставляет сайту: нет регистрации, форм, чатов, cookies и аналитики. Он выбирает исполнителя и нажимает
  **«Написать в WhatsApp»**. Ссылка `wa.me` открывает его WhatsApp с готовым текстом, и сообщение уходит **прямо исполнителю**.
  Сайт этого сообщения не видит.
- **Исполнитель** размещается сам, добровольно и по письменному согласию: заполняет карточку, отправляет её
  из своего WhatsApp на номер площадки и в любой момент может её изменить или удалить одним сообщением.
- Технически это **статический сайт**: HTML, CSS, JS и один публичный файл `site/data/listings.json`. Нет сервера, нет базы, нет секретов.

> ⚖️ Это техническое решение, построенное с учётом закона. Это не юридическое заключение. Перед запуском
> покажите юристу раздел «Закон» и тексты `privacy.html`, `consent.html`, `terms.html`.

## Какие данные обрабатываются

| | Прежняя версия (avtomaster-vezu) | Эта версия |
|---|---|---|
| Клиенты | Вход через Telegram (tg_id, @username, имя), телефон, город, гараж (марка, модель, **госномер**), заявки, геолокация, фото, чат по заказу, отзывы, лиды гостей (имя + телефон + хеш IP). Всё хранится в Supabase (проект VEZU, регион **eu-central-1, Франкфурт**). Плюс внешние скрипты: Google Fonts, Telegram, jsDelivr | **Ничего.** Нет форм, входа, cookies, аналитики и внешних запросов. Сообщение клиента уходит напрямую исполнителю через WhatsApp |
| Исполнители | Профиль, телефон, адрес, фото, рейтинг и отзывы, входящие заявки клиентов — всё в Supabase | Только поля карточки, которые исполнитель **сам** согласился опубликовать: название, категория, город, услуги, рабочий WhatsApp, район, часы, описание, фото (по желанию) |
| Подтверждение согласия | Галочка в профиле | Сообщение исполнителя с текстом согласия из его WhatsApp + запись в журнале **на компьютере оператора** (не в репозитории) |
| Удаление | Кнопка «Удалить мои данные» | Одно сообщение с номера из карточки, удаление за 1 рабочий день, `tools/listings.py remove` |
| Посетители | localStorage: сессия, черновики, избранное, «мои заказы» | localStorage: только выбранная тема |

Проверка при каждой публикации (`.github/workflows/pages.yml`): в карточках только разрешённые поля, у каждой есть версия
согласия, а на сайте нет внешних скриптов, шрифтов и счётчиков. Шрифт Manrope лежит в репозитории (OFL).
Политика CSP запрещает загрузку чужого кода, а `referrer` отключён.

### Локализация (ст. 12) — честно о рисках

Сайт размещён на GitHub Pages (США), и файл карточек тоже хранится на GitHub. Буквально это «база с персональными данными» за пределами РК.
Что сделано, чтобы снизить риск:
1. Данные **только публичные**, их публикует сам человек по согласию, включая трансграничную передачу.
2. **Основной экземпляр** реестра и журнал согласий хранятся у оператора в РК (папка `~/avtomaster24-soglasiya` на его компьютере, плюс локальная копия репозитория). Сайт — публичная копия.
3. Данных клиентов нет вообще.

Варианты на выбор (решает владелец вместе с юристом):
- **A. Пилот как есть** (сейчас): GitHub Pages + согласие на трансграничную передачу. Бесплатно. Остаётся риск толкования ст. 12.
- **B. Рекомендуется для запуска с деньгами:** тот же сайт на **хостинге в РК** (ps.kz, hoster.kz, QazCloud и т. п.). Это статика: папку `site/` просто копируют на хостинг,
  стоимость — от нескольких тысяч тенге в месяц. GitHub остаётся только хранилищем кода, а `listings.json` можно не хранить в публичном репозитории.
- **C.** Не держать номера в файле совсем, а только ссылку `wa.me` на WhatsApp Business исполнителя. Риск почти тот же: номер виден в ссылке.

## Как исполнитель размещается и удаляется

1. Исполнитель заполняет карточку на странице **«Разместиться»** (`join.html`) и видит предпросмотр. До отправки данные никуда не уходят.
2. Отмечает три галочки (согласие, «номер мой», соглашение), пишет ФИО (только для согласия) и нажимает **«Отправить в WhatsApp»**.
   Открывается WhatsApp с готовым текстом на номер площадки (`ADMIN_WHATSAPP` в `site/js/config.js`). В тексте есть согласие и машинный «Код карточки: AM1:…».
3. Оператор проверяет, что сообщение пришло **с того же номера**, что указан в карточке, и выполняет:
   ```bash
   python3 tools/listings.py add - --sender "+7 701 …"   # вставить текст заявки целиком, затем Ctrl+D
   git add -A && git commit -m "Карточка …" && git push   # через 1–2 минуты карточка на сайте
   ```
   Публичные поля попадут в `site/data/listings.json`, а ФИО и полный текст — в журнал `~/avtomaster24-soglasiya/zhurnal.jsonl` (в git не попадает).
4. **Удаление:** исполнитель жмёт «Удалить карточку и отозвать согласие» на странице «Разместиться» → приходит сообщение →
   `python3 tools/listings.py remove <id>` → `git push` → ответ исполнителю. Срок — 1 рабочий день.
5. Раз в месяц: `python3 tools/listings.py purge` удаляет карточки, у которых закончился срок (12 мес.). Продление — командой `extend`.

**Личная визитка-ссылка без каталога:** на той же странице кнопка «Сделать визитку-ссылку и QR». Все данные зашиты
в часть ссылки после `#`, которую браузер не отправляет на сервер. Площадка такие визитки не получает и не хранит. На странице есть кнопка «сообщить, если номер указан без согласия».

## Бизнес-модель (сайт → `pricing.html`)

| Что | Цена (предложение, поменяйте) | Почему работает без данных клиентов |
|---|---|---|
| Базовая карточка | 0 ₸ | Наполняет каталог; исполнитель получает клиентов напрямую |
| ⭐ Топ в категории и городе | 3 000 ₸/мес | Деньги — за место в выдаче, а не за данные |
| ✔ Проверен | 5 000 ₸/год | Проверка по открытому реестру БИН, адресу или видеозвонку, без копий документов |
| 🖨 Печать визиток и QR-наклеек | по запросу | QR ведёт на карточку |
| 🏙 Франшиза города ([avtomaster-franshiza](https://github.com/avtomaster24bot-lab/avtomaster-franshiza)) | доля выручки города | Представитель продаёт Топ, Проверен и печать по общим правилам о данных |
| Реклама без слежки | фиксированно за город и месяц | Баннер-картинка без счётчиков и рекламных сетей |

Комиссии с заказов нет и быть не может: площадка не видит заказов. Показать исполнителю, что клиенты пришли с сайта, можно
без слежки: в первом сообщении клиента уже стоит «Нашёл вас на АвтоМастер24». Оплата — по счёту (Kaspi или перевод), сайт платежи не принимает.

## Что заполнить перед запуском

- `site/js/config.js` → `OPERATOR`: ИП/ТОО, БИН/ИИН, e-mail. Без этого текст согласия неполный (ст. 8 п. 4 пп. 1). Пока поля пустые, на страницах документов показывается красная пометка.
- Проверить `ADMIN_WHATSAPP`: сейчас стоит номер из прежнего сайта (`DISPATCH_WHATSAPP`).
- Включить двухфакторную защиту на аккаунте GitHub.
- Решить вопрос локализации (вариант A, B или C выше) и показать документы юристу.
- Примеры карточек (`demo: true`, номер +7 000 000 00 00) показываются, только пока в городе нет настоящих карточек.

## Структура

```
site/                 сайт (публикуется на GitHub Pages)
  index.html          каталог: город, категория, поиск, «Написать в WhatsApp»
  card.html           визитка: ?id=<id> из каталога или #d=<код> (личная ссылка)
  join.html           разместиться / изменить / удалить
  pricing.html        тарифы
  privacy.html, consent.html, terms.html   политика, согласие, соглашение
  data/listings.json  публичный реестр карточек
  assets/listings/    фото исполнителей (только присланные ими)
  js/                 config.js (настройки), common.js, catalog.js, cards.js, card.js, join.js, qr.js, vendor/qrcode.js (MIT)
pages/                исходники HTML; общие блоки — tools/partials/; сборка: python3 tools/build_pages.py
tools/listings.py     реестр карточек: add / edit / top / verify / extend / remove / purge / list / check
```

Локальный запуск: `cd site && python3 -m http.server 8000` → http://localhost:8000
